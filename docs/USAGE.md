# 日迹使用说明

[返回项目首页](../README.md)

一个本地工作留痕桌面应用，使用 Rust + Tauri 2 + Vue 3 + TypeScript。日常记录无需联网，工作数据保存在本机 SQLite 数据库。

## 已实现

- 按日期记录备忘、工作进展与问题，添加标签，编辑和删除。
- 按日期维护待办清单，勾选完成状态，记录完成时间。待办可选填项目、优先级、预估耗时和实际耗时。
- 未完成的待办可顺延到次日，或在往日有积压时一键顺延到当前日期；顺延保留首次计划日期并累计次数。
- 写记录支持粘贴和上传图片，多图预览、移除和纯图片记录；图片随记录保存在本机。
- 日历跳转、全文搜索，统计概览支持按周、月、年查看记录天数、待办完成率、实际耗时、预估准确度、连续记录天数、完成趋势、项目分布、积压待办、记录热力图和手记标签。
- 统计概览可导出所选周期的待办明细 CSV。
- 用户主动选择日报、周报或月报，选择日期范围和报告风格；报告固定使用待办事项。
- 简洁汇报、详细汇报与个人复盘；AI 模式支持补充要求。
- 离线本地整理，或调用用户配置的 OpenAI 兼容 Chat Completions 接口。
- 报告历史、生成时的来源快照、复制、Markdown 导出。
- JSON 备份与合并导入。重复 ID 保留当前数据，整个导入经过验证后在同一事务中完成。

## 启动

Windows 上可直接运行打包后的 `src-tauri/target/release/riji.exe`，或安装 `src-tauri/target/release/bundle/nsis/` 下的安装程序。也可双击根目录的 `启动日迹.bat`。

开发环境需要 Node.js 22.12+、Rust 1.90+、Windows C++ 构建工具和 WebView2。其他系统的依赖参见 [Tauri 前置要求](https://v2.tauri.app/start/prerequisites/)。

```powershell
npm install
npm run desktop
```

浏览器预览：

```powershell
npm run dev
```

访问 `http://127.0.0.1:1493`。预览使用独立的浏览器本地存储，与桌面数据库分开；AI 调用与系统凭据存储在桌面端运行。首次使用是空工作空间，点击记录区的写下工作进展入口开始记录，通过左侧日历切换日期。

## AI 配置

在数据与设置中填写接口地址、模型名称和可选 API Key。接口必须兼容 `/chat/completions`，并返回 `choices[0].message.content`。

- 远程接口填写 HTTPS 地址，例如服务商提供的 `/v1` 基地址。
- 本地 Ollama 可使用 `http://127.0.0.1:11434/v1`，模型填写本机已安装的名称。
- 接口地址也可直接填写完整的 `/chat/completions` 地址。
- 填写地址和 API Key 后，点击模型名称旁的刷新，从输入框下拉列表选择模型，也可手动填写。刷新使用当前表单，无需先保存；地址未变且密钥留空时使用已保存的密钥。列表来自同一服务的 `/models` 接口，不支持时会提示手动填写。
- 使用保存并测试连接会发起一次小型连接测试，不发送工作记录。

## 代码提交

在数据与设置的代码提交中，可选择 GitHub 或 GitLab（自建 GitLab 需填写站点地址，必须为 HTTPS）。点击获取令牌会在系统浏览器打开对应的令牌创建页：GitHub 需要 repo 读取权限（仅访问公开仓库时可用 public_repo），GitLab 需要 read_api。创建后把令牌粘贴到访问令牌中，点击测试连接确认账号，再勾选启用并保存。

- 令牌保存在系统凭据库，不写入 SQLite、浏览器存储或备份；切换平台或 GitLab 地址时需重新填写。
- 生成 AI 报告时，勾选附带我的提交记录后，应用只读取令牌所属账号在所选日期范围内的提交，仅发送提交标题、仓库、日期和短哈希，不含代码和正文，合并提交不计入。提交写入来源快照，可在报告中查看。
- 提交只作为进度参考，AI 不会把提交当作完成、验收或上线，也不据此计算完成率或工时。
- GitHub 通过提交搜索读取，GitLab 读取你参与项目的提交，并按你的账号邮箱或姓名匹配作者；单次最多 500 条提交，超出时请缩小日期范围。
- AI 报告仅在点击生成后发送选中日期范围与勾选的内容，生成前可查看来源。通常会产生服务商的调用费用。
- Windows 密钥保存在系统凭据管理器；macOS 使用 Keychain，Linux 使用 Secret Service。密钥不会写入 SQLite、浏览器存储或备份。
- 修改接口地址并留空密钥时会清除旧密钥，避免误用。更换服务请重新填写密钥。
- 单次输入限制为 60000 字符，超出时明确报错，不会静默截断。请求超时、认证失败或输出截断时不保存不完整报告。

报告统计由本地程序计算，AI 只负责整理文字。AI 的文字结论仍需用户确认。没有配置 AI 也可以使用本地整理生成完整报告。

## 报告模板

默认模板用于上级汇报：日报依次展示总体情况、重点工作与交付、风险与需协调事项、明日重点计划；周报突出本周总体情况、重点项目与节点进展、进度风险与需协调事项、下周重点计划；月报展示月度目标达成情况、主要成果与业务价值、未完成事项与原因、风险与需协调事项、下月重点计划。日报标题使用年-月-日，周报、月报在标题下单独展示所选日期范围。项目按 `1、2、` 编号，项目内事项按 `①②` 编号，数量随待办展开。已有两版旧默认模板自动更新，已自定义的模板与历史报告保留。

本地整理根据已完成待办列出项目成果，根据未完成待办列出重点任务；支持从 `项目名称：事项`、`【项目名称】事项` 或 `[项目名称]事项` 中提取项目，未提供项目的待办归入待办事项。实际影响、风险、需协调事项、未完成原因、预期交付及完成时间标记待确认，月度目标、验收标准及达成情况也需确认。AI 根据待办中明确记录的信息整理这些字段，缺少依据时标记待确认；不把未完成待办当成延期，不把待办完成率当成月度目标达成率，不把记录日期当成交付期限，也不因未记录问题就填写无。

在数据与设置中切换日报、周报、月报，分别编辑 Markdown 模板并保存。支持恢复当前类型的默认模板，模板变量可从折叠入口插入：`{{汇报摘要}}`、`{{月度目标达成情况}}`、`{{重点项目成果与实际影响}}`、`{{风险与协调事项}}`、`{{下阶段重点任务与交付}}`、`{{未完成事项与原因}}`，同时保留标题、日期、范围、概况、项目完成情况、项目计划、已完成待办、未完成待办与每日待办等原有变量。每个模板最多 10000 字，支持自定义占位符，如 `{{项目名称}}`、`{{完成的事项1}}`。单日日期变量使用报告范围结束日期；其他自定义字段在本地整理时标记待填写，在 AI 生成时仅根据待办填写，缺少依据时标记待确认。本地整理直接填充模板；详细汇报在模板缺少每日待办变量时补充按日列表。AI 使用所选模板的章节和顺序，具体文字仍需确认。

所选范围内没有待办事项时不能生成报告。工作记录、分类、图片和留痕统计照常保存与展示，历史报告保持原样。

## 待办、项目与耗时

新增待办时，点击待办清单底部的「添加待办」，会直接弹出「新增待办」窗口，在里面填写标题，以及项目、优先级、预估耗时和实际耗时，这些都是选填，只填标题也能直接添加。项目不固定：输入框会提示已用过的项目，也可以直接填写新项目。项目名最多 40 字，单行。没有填写项目时，仍兼容标题中的 `项目名称：事项`、`【项目名称】事项` 写法。

之后可在待办的更多菜单选择编辑，补充或修改这些内容。耗时可输入分钟数，也可输入 `1.5h`、`1h30m`、`2小时`；上限 100000 分钟。耗时由用户填写，应用不会自动计时，报告和 AI 也不会替用户估算或编造耗时，没有记录耗时的待办不会显示耗时。

勾选完成会记录完成时间，取消勾选会清除。统计趋势中的「完成」按完成当天计算；升级前创建的旧待办没有完成时间，按计划日期计算。预估准确度只统计同时填写预估与实际耗时的已完成待办。

顺延：待办菜单可把单条未完成待办顺延到次日；当天之前有未完成待办时，待办清单下方会出现提示，可一键顺延到当前所选日期。顺延会修改计划日期，保留首次计划日期并累计顺延次数；已完成的待办不会被移动。积压待办按首次计划日期计算拖延天数。

## 统计概览

周期可切换为周、月、年并前后翻页，各指标与上一周期对比。热力图和连续记录天数把待办与手记都算作留痕；手记不进入报告。导出 CSV 带 BOM，可直接用 Excel 打开，以 `=`、`+`、`@` 开头的内容会加前缀避免被当作公式。

## 日期与数据

日报使用所选日期；周报默认周一至周日，月报默认自然月。周报和月报可在日期范围日历中点选起止日、拖动框选，或直接填写开始与结束日期，支持跨月、跨年，包含起止两天。右侧所选范围会带入生成弹窗，本地整理与 AI 使用相同的范围筛选待办事项；工作记录仅用于留痕和统计，不进入新报告。报告天数按有待办的日期去重，留痕统计中的记录天数按有手记或待办的日期去重，待办完成率为已完成待办数 / 所选待办数；没有待办时显示暂无待办。

Windows 数据默认保存至 `%APPDATA%\com.riji.worklog\riji.db`。具体路径在数据与设置中显示。导出备份包含手记、图片、待办、报告、来源快照和报告模板，不包含 AI 地址或密钥。导入合并已有记录，不覆盖相同 ID；备份含模板时恢复模板，旧备份不改变当前模板。待办的项目、优先级、耗时、完成时间和顺延信息随备份保存；不含这些字段的旧备份仍可导入。

图片支持 PNG、JPG、WebP、GIF、BMP 与 AVIF。每条记录最多 9 张，单张上传不超过 20 MB；保存前缩放至最长边 2048 像素并压缩。图片以二进制独立保存在 SQLite，编辑或删除手记后，历史报告仍保留原始图片来源。备份格式为版本 2，兼容导入版本 1。新报告仅使用待办事项，AI 不接收工作记录或图片附件信息。旧报告的来源快照继续保留。

快捷键：`Ctrl + N` 写记录，`Ctrl + K` 搜索，记录编辑时 `Ctrl + Enter` 保存，`Esc` 关闭弹窗。

窗口每次启动以 1600×900 像素居中打开，可拖动边缘调整大小或使用右上角按钮最大化。

页面本身不出现右侧滚动条：顶部栏和侧边栏固定，宽度大于 1080 像素且高度足够时，手记时间线、待办列表、报告列表、报告正文和统计内容各自在组件内部滚动。窗口较窄或较矮时，改为内容区整体在顶部栏下方滚动。
